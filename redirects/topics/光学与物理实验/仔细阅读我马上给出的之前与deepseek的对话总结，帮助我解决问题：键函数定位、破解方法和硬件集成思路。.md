### 三、 硬件集成思路 (Hardware Integration Plan)

这是您当前的重点。我们将详细展开总结中提出的两个方案。

#### 方案A：快速绕过错误提示 (推荐优先尝试)

**目标**：找到并禁用“串口COM号读取失败”的错误弹窗，让软件认为硬件存在，从而可以手动操作新硬件并使用软件的计算功能。

**操作步骤**：
1.  **在Ghidra中定位错误弹窗函数**：
    -   打开Ghidra，搜索字符串 `"串口COM号读取失败"` 或类似的错误信息。
    -   在搜索结果中，查看是哪个函数引用了此字符串。
    -   顺藤摸瓜，找到调用这个弹出错误提示函数的上级函数。这个上级函数就是我们的目标（例如上表中的 `Error_ComNotFound`）。
2.  **分析判断逻辑**：
    -   在该函数中，会有一个条件判断（通常是检查串口打开是否成功、读取数据是否超时等）。
    -   找到导致跳转到弹窗代码的**条件跳转指令**（例如 `JZ`, `JNE`）。
3.  **修改二进制代码**：
    -   **思路**：反转判断逻辑，或者直接`NOP`掉（填充为`90 90`）整个弹窗调用。
    -   **方法一（推荐）**：找到 `JZ` (跳转如果为零) 并修改为 `JNZ` (跳转如果不为零)，或者反之。这样软件在检测失败时会认为成功。
    -   **方法二**：直接找到 `CALL `（调用弹窗函数）的指令，将其全部用 `NOP` 指令（`0x90`）覆盖，使其什么都不做。
4.  **使用工具修改**：同样使用 HxD 或 x64dbg，定位到上述指令的文件偏移地址，进行修改。
5.  **测试**：修改后，运行软件，错误弹窗应不再出现，软件界面正常加载。之后，您需要在外部用新硬件的控制程序驱动相移器，然后在软件中触发采集和计算。

#### 方案B：彻底集成 - Hook与DLL注入 (高阶、彻底)

**目标**：创建一个代理DLL，拦截软件发送给原相移器的所有串口命令，并将其“翻译”或“映射”为新相移器能理解的命令。

**操作步骤**：
1.  **识别通信协议**：
    -   使用 **串口监视工具**（如 **AccessPort**、**SerialSniffer**、**PortMon**）监控原软件与原硬件通信时发送和接收的**原始数据帧**。
    -   分析这些数据帧的结构，例如：`[起始符][命令码][数据长度][数据][校验和][结束符]`。理解每个命令的含义（如：`0xA1` = 步进一步，`0xB2` = 归零）。
2.  **定位关键函数**：
    -   在Ghidra中，搜索 Windows API 函数 `WriteFile` 的交叉引用。因为向串口写数据最终会调用此函数。
    -   分析哪个函数调用了 `WriteFile`，并传递了要发送的数据缓冲区指针。这个函数就是 `SerialPort_Write`。
3.  **开发Hook DLL**：
    -   使用 C/C++ 编写一个DLL项目。
    -   使用 **Microsoft Detours**、**minhook** 等Hook库，来钩住（Hook）目标函数 `WriteFile` 或您找到的 `SerialPort_Write` 函数。
    -   在您的钩子函数中，检查传入的**数据缓冲区**和**文件句柄**。如果句柄是通向相移器的串口，则拦截原始数据。
    -   **实现翻译逻辑**：根据步骤1分析出的协议，编写一个转换函数。例如：`if (original_cmd == 0xA1) { new_cmd = {0x55, 0x01, 0xFE}; }`。
    -   将转换后的新命令，通过真正的 `WriteFile` 函数发送到**新相移器**所连接的串口。
4.  **注入DLL**：
    -   使用诸如 **RemoteDLL**、**x64dbg** 的注入功能，或编写一个简单的加载器程序，将您编译好的Hook DLL注入到目标DSPI软件进程的地址空间中。
5.  **测试**：启动软件，您的DLL会自动工作，实现无缝控制新硬件。
