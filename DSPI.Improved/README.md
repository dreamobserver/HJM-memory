# DSPI Improved

这是依据 `Phase-shifting DSPI V3.2.exe` 的 PDB、反编译结果和本机 CatchBEST KSJ SDK 重建的可维护版本。它不修改原 EXE，原软件可以继续保留作对照。

## 已改进

- 条纹差分使用饱和运算，放大后不会发生 8 位回绕。
- 相位在内部始终保存为 `float` 弧度；相位差使用真正的模 `2π` 运算。
- 滤波对 `sin(φ)`、`cos(φ)` 分量作质量加权圆周均值，避免破坏 `0/2π` 边界。
- 增加“滤波 ×1”“一键滤波 ×5”“一键滤波 ×10”。
- 解包裹改为从最高质量像素开始的质量优先四邻域传播，降低低信噪比点过早传播错误的风险。
- 解包裹结果保留浮点值；0–255 仅用于显示，条纹级数由浮点峰谷相位差计算。
- 条纹对比度输出显式限制到 0–255。
- 条纹对比度改为可直接输入的 `0.1–100.0` 倍范围。
- 相机增益改用 CatchBEST 官方示例采用的 `KSJ_RED/GREEN/BLUE` 参数；单色 CCD 的 `KSJ_RED` 由 SDK 映射为 VGA 增益。
- 相机抓帧和参数设置串行化，避免拖动滑块时与采集线程并发访问 SDK。
- 相移控制器改为枚举所有 COM 口，并按配套 PztControl 软件的真实协议执行握手：`115200-N-8-1`、4 字节二进制指令、13 位 DAC。
- 界面加宽参数栏、重排参数值并支持滚动，避免高 DPI 下字体和值被裁切。
- 串口列表通过 Windows DOS 设备映射二次校验，过滤注册表残留的离线“幽灵 COM 口”。
- 支持右键拖动选择解包裹 ROI，以及离线打开包裹相位图验证算法。

## 构建与自检

```powershell
dotnet build -c Release
dotnet run -c Release -- --self-test
```

SDK 原生文件放在 `native/`，构建时自动复制到输出目录。程序按原软件行为使用 KSJ 枚举中的最后一台相机。串口列表读取自注册表 `HARDWARE\\DEVICEMAP\\SERIALCOMM`，不再依赖固定的 `\\Device\\VCP0` 名称。

部分 KSJ 型号只支持同步 `KSJ_CaptureRawData`，调用可选的 `KSJ_StreamStart` 或采集恢复接口会返回 `RET_NOTSUPPORT (-3)`。程序会兼容该返回值并继续使用同步采集，而不会误判为相机初始化失败。

相移串口使用从用户提供的“扫频干涉仪控制器软件”反编译确认的协议：`115200-N-8-1`；连接握手和电压命令格式为 `10 01 LL HH`，百分比电压按 `round(percent × 81.91)` 转换为 13 位 DAC 值。界面的“单步电压”默认 25%，四幅采集对应 0%、25%、50%、75%，可按实际 PZT 的 π/2 标定结果调节为 1–33%。

## 仍需真实硬件验证

算法自检可以离线完成，但 PZT 的电压—相位标定和实际光路只能在实验设备上确认。测试时请保留原程序，先使用静止物体验证四幅相移图和相位方向，再进行加载实验。
